### หมวดที่ 1: Python Backend Framework & Architecture
- **Framework ที่เลือก**: **FastAPI** (เน้นประสิทธิภาพสูง, Asynchronous, ตรวจสอบข้อมูลด้วย Pydantic, มี Swagger UI ทดสอบ API อัตโนมัติที่ `/docs`) [ตัดสินใจแล้วโดยคุณ Fahsai]
- **ORM / Database Access**: **SQLAlchemy 2.0** (Async ORM)

### หมวดที่ 2: ระบบสมาชิกและการพิสูจน์ตัวตน (User Authentication & Roles)
- **สิทธิ์ผู้ใช้งาน (User Roles)**: แบ่งเป็น 3 ระดับ [ตัดสินใจแล้วโดยคุณ Fahsai]
  1. `Admin`: ผู้ดูแลระบบทั้งหมด (จัดการผู้ใช้, กำหนดราคา/โปรโมชั่น, จัดการห้องประชุม, รายงาน)
  2. `Room Manager`: ผู้อนุมัติและดูแลห้องประชุมประจำแผนก
  3. `User / Member`: สมาชิกทั่วไป (ค้นหาห้อง, จองห้องได้ราคาส่วนลดสมาชิก, ดูประวัติการจอง)
- **การสมัครและสร้างบัญชีผู้ใช้ (User Account Creation)**: [ปรับปรุงโดยคุณ Fahsai]
  - **เปิดระบบให้ลูกค้า/พนักงานสมัครสมาชิกเองได้ (Self-Registration)** เพื่อรับสิทธิ์ราคาสมาชิก/โปรโมชั่น
  - **Admin** ยังคงสร้างและจัดการสิทธิ์บัญชีผู้ใช้งานในระบบได้เช่นกัน
- **การพิสูจน์ตัวตน (Authentication Standard)**: JWT (JSON Web Token) + Password Hashing (Bcrypt)

### หมวดที่ 3: เงื่อนไข รูปแบบการจอง และระบบราคา/โปรโมชั่น (Booking Modes, Rules & Pricing Engine)
- **รูปแบบการจอง (2 Booking Modes)**: [ตัดสินใจแล้วโดยคุณ Fahsai]
  1. **Member Booking (การจองสำหรับสมาชิกที่ Login)**: ได้รับราคาสมาชิกส่วนลดพิเศษ/โปรโมชั่น ดึงข้อมูลผู้จองให้อัตโนมัติ
  2. **Guest Booking (การจองสำหรับบุคคลทั่วไปที่ไม่ Login)**: จองได้ในราคาปกติ (Standard Rate) ต้องกรอกข้อมูลผู้ติดต่อ (ชื่อ-นามสกุล, อีเมล, เบอร์โทร, วัตถุประสงค์) และได้รับ **Booking Code** (เช่น `RM-88A92`) สำหรับติดตามสถานะ
- **ระบบตั้งราคาและโปรโมชั่นส่วนลด (Pricing & Promotion Engine)**: [ตัดสินใจแล้วโดยคุณ Fahsai]
  - **ราคามาตรฐาน (Standard Price)**: ราคาสำหรับบุคคลทั่วไป (Guest Rate)
  - **ราคาสมาชิก (Member Discount Rate)**: ราคาพิเศษสำหรับสมาชิกที่ Login เข้าใช้งาน
  - **ระบบโปรโมชั่น/รหัสส่วนลด (Promo Codes / Discounts)**: Admin สามารถกำหนดราคาโปรโมชั่น และเปอร์เซ็นต์/ส่วนลดพิเศษสำหรับสิทธิ์สมาชิกได้
- **ระบบอนุมัติการจองและกำหนดผู้อนุมัติ (Approval Workflow & Approver Assignment)**: [ตัดสินใจแล้วโดยคุณ Fahsai]
  - Admin/Room Manager ตั้งค่าได้รายห้องว่าห้องใดต้องผ่านการอนุมัติ (`requires_approval = True`) หรืออนุมัติทันที (`requires_approval = False`)
  - **สามารถตั้งค่ากำหนดบุคคลผู้อนุมัติ (Assigned Approver) รายห้องได้** (กำหนดว่าห้องใดให้ Admin หรือ Room Manager ท่านใดเป็นผู้อนุมัติ)
  - การจองจากบุคคลทั่วไป (Guest) เข้าสู่สถานะรออนุมัติ (`Pending Approval`) เสมอเพื่อความปลอดภัย
- **ข้อกำหนดระยะเวลาจอง (Time Constraints)**: [ตัดสินใจแล้วโดยคุณ Fahsai]
  - **การจองล่วงหน้า**: สูงสุดไม่เกิน **15 วัน**
  - **ระยะเวลาการจองต่อครั้ง**: ขั้นต่ำ **30 นาที**, สูงสุดไม่เกิน **1 ชั่วโมง**
- **กฎการยกเลิกการจอง (Cancellation Policy)**: ผู้ใช้สามารถกด **ยกเลิกการจองได้เองล่วงหน้าอย่างน้อย 3 วัน** ก่อนวันประชุม [ตัดสินใจแล้วโดยคุณ Fahsai]
- **การป้องกันการจองซ้ำ (Overlap Protection)**: ตรวจสอบและล็อกไม่ให้เวลาจองทับซ้อนกันในห้องเดียวกันในระดับ Database Constraint / Transaction

### หมวดที่ 4: การจัดการห้องประชุมและอุปกรณ์ (Room & Equipment Management)
